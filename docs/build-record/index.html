A framework already on version 17

By the time any of this reached git, the analysis prompt was called trading-copilot-v17.md and ran to thirty-five thousand characters. Sixteen prior versions were written, used and replaced in chat windows with no version control at all. They are not recoverable. The framework's own rule — never overwrite a version, always add a new integer file — was written by someone who had already lost sixteen.

Two more prompts land the same week: a thesis-review pass and a long-form article writer. The writing engine and the analysis engine were separate from the very beginning, which is why the posts later read like they were edited by someone who was not the analyst.

BrokeJun 30 – Jul 20

Twenty-two calls. One entry.

The seeded book covers three weeks of a bull market. Its verdicts: seven No Trade, five Watchlist, four Hedge, one Accumulate, one Armed, one Setup Forming, one Top watchlist.

One row out of twenty-two was an actual position. The framework was not producing bad calls. It was producing almost no calls at all.

Nobody noticed for four weeks, because a system that says no to everything is never visibly wrong.

What is still wrong

Nothing reconciles the orders. The book records what was decided; no process pulls the actual brokerage orders and flags anything missing. Until it exists, the logging discipline only holds where somebody runs the command.

Every market routine fires in the worst window for reach. The data says evenings; the market says mornings. That tradeoff is undecided and it is a real one, not an oversight.

The machine's own instructions have gone stale in at least one place — the operating file still says threads are unsupported, which stopped being true on August 5.
